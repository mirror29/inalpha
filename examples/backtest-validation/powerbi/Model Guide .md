# Power BI Prototype — Data Model, Lineage Dashboard & Drill-Through

## Overview

This document explains how to reproduce the Power BI prototype using the synthetic CSV fixture generated by the Python dataset generator.

The prototype consists of:

1. Importing the generated CSV datasets into Power BI.
2. Building the relational data model.
3. Creating the Realised PnL measure.
4. Creating the lineage/decomposition-tree dashboard.
5. Configuring tooltips and drill-through.
6. Creating the run-performance dashboard.
7. Connecting the two pages through drill-through.
8. Verifying that filtering and drill-through work correctly.

The prototype is intended to demonstrate how candidate → backtest run → trade/fill lineage can be explored interactively.

---

# 1. Input Data

The Power BI model uses the CSV files generated by the synthetic Python dataset generator.

The generator produces three files:

- `candidates.csv`
- `backtest_runs.csv`
- `backtest_trades.csv`

These represent three related levels of the data:

| Table | Purpose |
|---|---|
| `candidates` | Strategy/candidate-level information |
| `backtest_runs` | Backtest execution and performance information |
| `backtest_trades` | Individual trade/fill-level information |

The Python generator should be executed first so that these CSV files are available locally.

---

# 2. Importing the Data into Power BI

Open Power BI Desktop.

From the **Home** tab:

1. Select **Get data**.
2. Select the appropriate CSV/Text source option.
3. Import:
   - `candidates.csv`
   - `backtest_runs.csv`
   - `backtest_trades.csv`
4. Load all three datasets into the Power BI model.

The three imported tables should appear in the **Data** pane.

The expected table names are:

- `candidates`
- `backtest_runs`
- `backtest_trades`

---

# 3. Building the Data Model

After importing the CSV files, open **Model view**.

The model should represent the following lineage:

    candidates
        |
        | 1 : *
        v
    backtest_runs
        |
        | 1 : *
        v
    backtest_trades

The relationships are based on the following keys:

    candidates[candidate_key]
            ↓
    backtest_runs[candidate_key]

    backtest_runs[run_key]
            ↓
    backtest_trades[run_key]

## 3.1 Candidate → Backtest Run Relationship

Create a relationship between:

`candidates[candidate_key]`

and:

`backtest_runs[candidate_key]`

The intended cardinality is:

**One-to-many (1:*)**

The `candidates` table is the **one** side and `backtest_runs` is the **many** side.

---

## 3.2 Backtest Run → Backtest Trade Relationship

Create a relationship between:

`backtest_runs[run_key]`

and:

`backtest_trades[run_key]`

The intended cardinality is:

**One-to-many (1:*)**

The `backtest_runs` table is the **one** side and `backtest_trades` is the **many** side.

# 4. Creating the Realised PnL Measure

Create a new measure in Power BI.

The measure is:

    Realised pnl =
        backtest_runs[metric_initial_cash]
        - backtest_runs[final_equity]

This measure is used as the primary value for the lineage/decomposition analysis.

> **Important:** The current prototype measure does not include tax calculations.

The measure is intended to provide the PnL value used by the prototype dashboard.

---

# 5. Creating the Lineage Dashboard

The first dashboard page is the lineage/exploration page.

Its purpose is to allow the user to start from the overall PnL and progressively break it down through:

    PnL
      ↓
    Candidate
      ↓
    Run
      ↓
    Symbol
      ↓
    Timeframe

## 5.1 Add the Decomposition Tree

Create/select the **Decomposition Tree** visual in Power BI.

The visual should use the `Realised pnl` measure in the **Analyze** field.

### Analyze

`Realised pnl`

### Explain by

Add the following fields in this exact order:

1. `candidates[candidate_key]`
2. `backtest_runs[run_key]`
3. `backtest_runs[symbol]`
4. `backtest_runs[timeframe]`

The order is important because the decomposition tree uses these fields sequentially when drilling into the PnL.

The intended hierarchy is therefore:

    Realised pnl
        ↓
    candidate_key
        ↓
    run_key
        ↓
    symbol
        ↓
    timeframe

---

# 6. Decomposition Tree Tooltips

Configure the decomposition tree's tooltip fields using the relevant fields shown in the prototype.

The tooltip fields are:

- First side
- Total Quantity
- First Intent
- Number of trades
- Total fees
- Calmar
- Payoff ratio
- Fitness

These tooltip values provide additional information when inspecting an individual point/node in the decomposition tree.

The purpose is to allow the user to inspect more context without placing every metric directly into the main visual.

# 7. Drill-Through Configuration

The run-performance dashboard is accessed through Power BI drill-through.

The drill-through configuration should be created on the dashboard page containing the run-performance details.

Enable:

- **Cross-report: On**
- **Keep all filters: On**

The drill-through fields are:

- `candidate_key`
- `run_key`
- `symbol`
- `timeframe`

These filters allow the selected lineage context to be passed into the detailed run-performance page.

The configuration should therefore preserve the selected:

    Candidate
        ↓
    Run
        ↓
    Symbol
        ↓
    Timeframe

when the user drills through.

---

# 12. Dashboard Filtering

The dashboard should preserve the filters passed from the lineage dashboard.

The drill-through/filter context should include:

- `candidate_key`
- `run_key`
- `symbol`
- `timeframe`

For example, a selected lineage path could result in:

    candidate_key = candidate_031
    run_key = run_028
    symbol = SOL/USDT:USDT
    timeframe = 1h

The run-performance dashboard should then display the corresponding filtered metrics and trade data.

# 13. Connecting the Two Pages

The two pages are connected through Power BI's drill-through functionality.

The workflow is:

    Lineage Dashboard
            ↓
       Select PnL
            ↓
      Select Candidate
            ↓
         Select Run
            ↓
       Select Symbol
            ↓
      Select Timeframe
            ↓
    Right-click selected node
            ↓
       Drill through
            ↓
    Run Performance Dashboard

The detailed dashboard should inherit the selected filters.

---

# 14. Verifying the Decomposition Tree

After creating the model and dashboards, verify that the decomposition tree behaves correctly.

Start with the `Realised pnl` value.

The decomposition tree should provide the option to split the value using one of the available `Explain by` fields.

For example:

    Realised pnl
        ↓
    candidate_key

When the PnL is selected, Power BI provides options to split the value by:

- High value
- Low value

Select the required option.

The tree should then display the candidate-level breakdown according to the selected option.

---

# 15. Continue Through the Explain-By Hierarchy

Continue the process through the configured order:

    candidate_key
        ↓
    run_key
        ↓
    symbol
        ↓
    timeframe

The order matters.

The tree should therefore progressively answer:

    Which candidate contributes to the selected PnL?

            ↓

    Which run belongs to that candidate?

            ↓

    Which symbol does that run represent?

            ↓

    Which timeframe does that run use?

---

# 16. Inspecting a Data Point

After expanding the decomposition tree, right-click a node/point other than the root PnL value.

Power BI provides options such as:

- Copy
- Show data point as a table
- Show as a table
- Include
- Exclude
- Drill through

These options allow the selected data point to be inspected further.

---

# 17. Show Data Point as a Table

Selecting:

**Show data point as a table**

should display the underlying values associated with the selected point.

This is particularly useful for checking the tooltip-related values configured for the decomposition tree.

It provides a way to inspect the data behind the selected visual point.

---

# 18. Show as a Table

Selecting:

**Show as a table**

provides a tabular representation of the visual's data under the current filter context.

This allows the user to inspect the data associated with the current decomposition-tree state.

---

# 19. Drill Through

Right-clicking a suitable node should also provide:

**Drill through**

The drill-through submenu should contain the run-performance dashboard page.

Select that page.

Power BI should navigate to the run-performance dashboard while preserving the selected filter context.

For example:

    Candidate
        ↓
    Run
        ↓
    Symbol
        ↓
    Timeframe

The destination page should therefore be automatically filtered according to the lineage selection.
